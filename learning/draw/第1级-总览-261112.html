两套编号，别混

seq
已提交、写进 jsonl 的 event。落盘就有，Host 重启也在。
revision
模型正在说的草稿 assistant-stream，只在 Host 内存。每个 Agent 一个计数器，跨 step 一直加，Host 重启后清零。
连接点：草稿的 start 帧带 startedAfterSeq，标明它接在哪条已提交事件之后。刷新时两者各有一个切口：cursor（seq）和 ordinal（图 5）。
packages/api/session-controller/src/client/sessions/session.ts beginSubmission　· packages/api/session-controller/src/commands.ts hasPromptRequest　· 分层表：docs/subsystems/web-client.zh.md

两个 ID 分两层

  • 外层 rpcId：管这一次网络调用。
  • 里层 requestId：管"用户发的这一条消息"，Host 记进日志 source.rpcId，用来去重。
  • 浏览器不自动重发；手动再点一次会生成新 ID，模型会回答两次。

request 里值得记的两个字段

  • mode：queue 自成新一轮；steer 在当前轮下一个 step 边界并入，不打断正在进行的调用。
  • content：数组，可混 text / image / file；空数组表示让失败停下的会话继续。
  • clientTimeZone 写进消息来源，让模型知道用户那边几点。

"已收下"看哪路先到：HTTP 回执，或 follow 流里出现带自己 requestId 的 Inbox 行（packages/client/ui-conversation/src/client/service.ts）。

为什么写进日志

模型看到的东西都能从日志重建（重放、恢复、fork）；旧消息不变，请求前缀稳定，命中缓存。

记一句：每步结束就落盘，上下文只追加不改。日志是唯一可信的来源，模型看到什么都能从它重建。

漏帧：浏览器这头

发现 revision 不连续，就当线路故障，自动重连。首帧是带草稿底稿的 snapshot，已显示的内容保留（packages/api/session-controller/src/client/transport.ts）。

漏帧：Host 累积器这头

发现跳号，就丢掉这次的半截草稿，只对齐编号（packages/api/session-controller/src/assistant-stream.ts）。

记一句：草稿按 revision 实时推、只在内存；成品按 seq 一步一落盘。漏帧时宁可不给，也不给错，最终以落盘版本为准。

原因userdisposed

下一轮模型看得到半截回答

每步都从日志重建上下文。interrupted 的 assistant/message 在历史里，所以发"继续"时模型能引用断掉的那句接着写；assistant/attempt 不进上下文。

记一句：停止 = abort 一个 signal。收到多少写多少，写成 interrupted 就会进下一轮的上下文。

不漏不重

  • 监听器在拿快照之前就挂上了，即 0.2 的"先订阅增量，再拿全量"。
  • 两个切口保证增量和快照不重叠。
  • 浏览器以快照的 revision 为起点，要求下一帧正好 +1，否则按图 3 的跳号重连（transport.ts；只读了代码，没有实测）。

不是一次全拿

打开窗口：最近至少 50 条消息、至少 2 轮、最多 500 条。hasMore: true 时往上滚动再 loadOlder 分页（packages/api/session-controller/src/client/sessions/session.ts）。

Host 重启过再刷新 实测

cursor 199 是 session/end-seed，assistantStream {revision: 0}：内存草稿清零。Ctrl+C 时已写成 interrupted 的半截内容会从 records 回来；回不来的是后续输出，那一轮已经记为 aborted: disposed。

记一句：刷新 = 重新订阅。Host 给一份"已落盘 + 草稿底稿"的快照，再用 seq 和 ordinal 两个切口接上增量。

盖住图，自己答一遍

1. requestId 为什么必须由浏览器生成，而不是 Host？

它用来去重"用户发的这一条消息"。会重发的是浏览器，只有它事先生成，同一个 ID 再来时 Host 才能认出来、直接回 accepted、不重复入队。

2. 为什么 cancel 请求不带 requestId？

"停下"做几次都一样，不需要去重。请求体只有 sessionId。

3. 发送后 0.1 秒就点停止，和说到一半点停止，日志有什么不同？下一轮模型看得到哪个？

第一块还没到：只写 assistant/attempt，不进上下文。收到过思考或正文：写 interrupted: true 的 assistant/message，下一轮模型看得到。

4. seq 和 revision，哪个在 Host 重启后清零？为什么？

revision。它编的是只在 Host 内存里的草稿；seq 编的是写进 jsonl 的事件。

5.（第 0 级留的题）快照里已有的东西，增量又推一次，客户端收到两次怎么办？

在 session/follow 上不会发生：快照带两个切口，落盘事件按 cursor（seq）切，之后从下一个 seq 推；草稿按 ordinal 切，已折进底稿的帧不再重推。
